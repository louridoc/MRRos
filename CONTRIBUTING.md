# Contributing to MRRos

Thanks for your interest. This file is the developer reference: layout, commands, conventions and
workflow. For setup and usage see the [README](README.md); for the plan and design decisions see
[`docs/PLAN.md`](docs/PLAN.md).

Locked decisions live in `docs/PLAN.md`. To change one, propose an ADR in `docs/adr/` rather than
reworking it in a PR.

## Layout

- `ios/project.yml` → XcodeGen → `ios/MRRos.xcodeproj` (generated by `tools/xcodegen.sh`, not committed).
- `ios/MRRos/`: thin app target (SwiftUI views, wiring). No logic that belongs in a package.
- `ios/Packages/<Name>/`: local SwiftPM packages, each with tests. Dependency order (a lower
  package may not import a higher one):
  `ROSMessages` → `ROSBridgeClient`, `TFKit`, `URDFKit`, `ARBridgeTransport`, `LiDARScan`
  → `AlignmentKit`, `MeshProvider` → `SceneLibrary`, `RobotModel` → `AppCore`.
- `ros2_ws/src/ar_bridge`: companion node (rclpy). HTTP API for point clouds, meshes and scenes.
- `ros2_ws/src/ar_dev_bringup`: dev launch (rosbridge, robot_state_publisher, mock joints, RViz,
  optional MoveIt).
- `tools/`: env setup, build/test wrappers, integration tests, mesh conversion.
- `docs/`: plan, ADRs, protocols (`docs/protocols/`), test checklists (`docs/testing.md`).

## Commands

| What | Command |
|---|---|
| ROS env (macOS/RoboStack, once per distro) | `tools/ros-env.sh create <humble\|jazzy\|lyrical>` (envs `ros_<distro>` under `~/micromamba`) |
| Run anything in a distro env | `tools/ros.sh <distro> <cmd…>` (sources `ros2_ws/install/<distro>` if built) |
| Build the ROS workspace | `tools/ros-build.sh <distro>` → `ros2_ws/{build,install}/<distro>` |
| Dev bringup | `tools/ros.sh jazzy ros2 launch ar_dev_bringup dev.launch.py robot:=crx30ia` (`crx20ial`, `ur30`, `ur20`, `ur10e`; `rviz:=false frozen:=true` for headless) |
| + MoveIt | add `moveit:=true` (move_group + octomap from `/mrros/static_cloud`); Plan & Execute drives the simulated `mock_joints` controller; `execute:=false` for planning only |
| ar_bridge alone (any workspace) | `ros2 launch ar_bridge ar_bridge.launch.py [scenes_dir:=… http_port:=… params_file:=…]` (all parameters: `ar_bridge/config/ar_bridge.yaml`) |
| MoveIt scene check | `tools/ros.sh jazzy python tools/moveit_scene_check.py --robot ur10e [--mesh] [--execute]` (CRX: bringup with `positions:="0,0.7,0,0,0,0"`) |
| ROS unit tests | `cd ros2_ws && ../tools/ros.sh <distro> pytest -q` |
| Python lint | `uvx ruff check ros2_ws tools` (target py310 = Humble) |
| Swift package tests (macOS) | `tools/ios-test.sh [Pkg…]` |
| Generate the Xcode project | `tools/xcodegen.sh` (signing: see README, "Build the app") |
| Simulator build | `tools/ios-build.sh` (generic destination; pass a simulator name to target one) |
| Integration tests vs local ROS | `tools/it.sh <distro> [robot]` |
| Liveness test (silent peer) | `tools/it-deadbridge.sh <distro>` |
| Re-record rosbridge fixtures | `tools/ros.sh <distro> python tools/record-fixtures.py` (bringup running) |
| New package | `tools/new-module.sh <Name> [Dep1,Dep2]` |
| Regenerate the app icon | `uvx --with pillow python tools/icon/make_icon.py [--preview out.png]` (needs `rsvg-convert`) |
| Format one file | `tools/hooks/format.sh <file>` (SwiftFormat / ruff) |

Distro rules: ROS-side Python stays 3.10-compatible (Humble). The only file allowed to branch on
the distro is `ar_dev_bringup/distro.py`. External description sources are pinned per distro in
`tools/external.repos.tsv`. CI runs the ROS jobs on Humble, Jazzy and Lyrical.

## Conventions

- Swift 6 with strict concurrency. Packages are platform-neutral where possible (they build and
  test on macOS); anything importing ARKit/RealityKit lives behind `#if canImport(...)` or in the
  app target.
- No force-unwraps or `try!` in packages. Errors are typed enums. Logging via `os.Logger` with
  subsystem `io.github.louridoc.mrros` and the package name as category.
- Frames: ROS is Z-up/X-forward, ARKit is Y-up/−Z-forward. The only conversion lives in
  `AlignmentKit` (`FrameConventions`). Never hand-roll axis swaps elsewhere.
- Every package has tests (swift-testing). A module is done when its tests pass on macOS and its
  exit test in `docs/PLAN.md` is met.
- Python: `ruff` clean, type hints, `pytest`. ROS nodes are `rclpy`, with parameters declared.
- Wire formats are shared between Swift and Python (PLY clouds, PLY meshes, the scene format).
  Change both sides in the same commit; the cross-language fixtures in
  `ros2_ws/src/ar_bridge/test/fixtures/` are written by the Swift tests and checked by Python.
- Commits: conventional (`feat(TFKit): …`, `fix(ar_bridge): …`). One milestone = one branch + PR.
- Never commit lab IPs, team IDs or other personal settings: use `~/.mrros/config` (read by
  `tools/xcodegen.sh`) or the app's settings.

## Workflow per module

1. Read the module's row in `docs/PLAN.md` and its section in `docs/testing.md`.
2. Write the test first when the behaviour is specifiable (parsers, math, codecs).
3. Implement, run `tools/ios-test.sh`, then the integration tests (`tools/it.sh`) if it touches ROS.
4. Update the `docs/testing.md` checklist, and the layout above if the structure changed.

## Robot meshes

Bundled meshes are generated, not hand-edited: see `tools/meshes/convert.py` and
[`docs/adding-a-robot.md`](docs/adding-a-robot.md). They keep their upstream licenses
([`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)). After converting Universal Robots meshes
that carry the UR graphical-documentation terms, run `tools/meshes/stamp_notice.py` to restore
their copyright notice.
